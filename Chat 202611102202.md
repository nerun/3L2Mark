## Como usar

```bash
# once: toolchains (Debian)
sudo apt install gcc g++ default-jdk-headless php-cli mono-mcs

python3 codebench.py --selftest   # checks compilers and the battery itself, no model needed
python3 codebench.py              # runs the battery against http://127.0.0.1:9931
python3 codebench.py --compare    # ranking of all models already tested
```

Você sobe o modelo com os parâmetros que quiser e roda o script. Ele não envia temperatura nem sampling (usa o que está no servidor), só `seed` e `max_tokens`. No fim grava `results/<modelo>/<data>/report.md` com a nota de 0 a 100, mais a resposta e o código de cada tarefa.

## O que é medido

São 21 tarefas, todas corrigidas por testes ocultos (cerca de 250 no total):

| Categoria | Python | C/C++ | C# | PHP | Java | SQL |
|---|---|---|---|---|---|---|
| Escrever a partir de especificação | semver | livro de ofertas (C++) | planilha com ciclos | CSV RFC 4180 | calculadora racional | esquema com triggers e views; 2 consultas (recursiva e window) |
| Achar bugs ocultos | 5 bugs | 6 bugs (C, com ASan/UBSan) | 5 bugs | 6 bugs | 5 bugs | consulta e script de triggers |
| Otimizar | sim | sim (C) | sim | sim | sim | consulta + índices |

- **Nota:** é a média da fração de testes ocultos que cada resposta passou. Não há julgamento visual nem outro modelo como juiz.
- **Bugs ocultos:** são típicos de cada linguagem (por exemplo `Integer ==` em Java, `strpos` na posição 0 em PHP, cópia de struct em C#). O prompt não diz quantos são, e cada um tem testes próprios, então consertar 3 de 5 dá nota parcial.
- **Otimização:** entradas grandes com limite de tempo. Nas minhas medições a versão rápida ficou abaixo de 1 s, contra limites de 2 a 4 s, e o original lento não terminou nem com o limite multiplicado por 5.
- **SQL:** roda no SQLite embutido do Python, sem instalar banco.

## Para diferenciar modelos parecidos

- Use `--runs 3`: a nota vira média e o relatório mostra o desvio-padrão. Com uma rodada só, diferença de poucos pontos é ruído.
- O `--compare` gera uma tabela por tarefa, modelo a modelo, além de critérios de desempate fora da nota (tarefas 100% resolvidas, taxa de compilação, tok/s).

## Pontos de atenção

- **Código do modelo:** o script compila e executa o que o modelo escreve, com seu usuário, em diretório temporário e com limites de tempo e memória.
- **C#:** se houver .NET SDK ele é usado; senão, Mono (`mcs`). O prompt informa o alvo ao modelo, então compare modelos sempre com o mesmo (`--csharp mcs` força o Mono).
- **Piso de 25% em otimização:** devolver o programa original sem mudanças pontua cerca de 25% nessas tarefas (os testes pequenos de corretude), para que quebrar o programa valha menos que não mexer.
- **Looping:** cada resposta tem teto de 16384 tokens e 30 min (`--max-tokens`, `--task-timeout`). Se a execução cair, `--resume <pasta>` continua de onde parou.
